# 未解决问题与第二阶段计划

## 基线中已确认的问题

1. 当前 `tju_connect()` 直接将 socket 设置为 `ESTABLISHED`，尚未实现真实三次握手和握手重传。
2. 当前 `tju_accept()` 直接构造连接，未维护真正的半连接/已完成连接队列。
3. 当前 `tju_send()` 使用固定 `seq=464`，没有未确认队列、累计 ACK、窗口滑动或可靠重传。
4. 当前 `tju_handle_packet()` 只追加 payload，未校验序号、checksum、重复、失序和重叠。
5. 当前 `tju_recv()` 采用忙等，条件变量和并发边界仍需重新设计。
6. 当前 `tju_close()` 直接返回 0，未实现 FIN 状态机、TIME-WAIT 和资源回收。
7. 当前发送/接收窗口结构只有骨架字段，`rwnd`、`cwnd`、`ssthresh` 和 `FlightSize` 尚未成为可验证的协议状态。

## 第二阶段计划

1. 先实现并测试连接建立、重复报文处理和连接关闭状态机。
2. 再实现分段、序号/确认号、发送/接收缓冲区和累计确认。
3. 加入 checksum、失序/重复/重叠处理、RTT/RTO、Karn 算法和超时/快速重传。
4. 完成 `rwnd`、窗口滑动、零窗口探测和基本 SWS 避免。
5. 每个小步修改都编译、运行并保存日志/pcap；阶段末用 100 MB 数据做可靠传输验证。

## 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| VM 网卡或 qdisc 配置不一致 | 测试不可复现 | 每次记录 `ip route`、`tc -s qdisc` 和参数 |
| 接收线程与应用线程竞态 | 丢数据、死锁 | 缩小锁范围，使用条件变量并做并发测试 |
| 误把 rwnd 当 cwnd | Reno 行为错误 | trace 同时记录 `rwnd/cwnd/FlightSize` |
| 重传报文参与 RTT 采样 | RTO 失真 | 记录采样来源，遵循 RFC 6298 Karn 算法 |
| 大文件缓冲区不足 | 可靠传输失败 | 先小文件，再逐步增加到不少于 100 MB |
